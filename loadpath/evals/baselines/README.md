# Eval baselines

`coarse.json` and `full.json` hold the scores `python -m loadpath.evals.run --baseline` compares against. Re-save one with `--save-baseline` only when a change is meant to move the numbers, and add a line here saying why.

## coarse.json history

- **2026-11-03 (after 87ad5d4).** Re-saved from main with whole cells (cut cells off), 21/21 pass. Big moves vs the Nov 1 baseline (ab4bf9e), checked before saving:
  - The Nov 1 baseline was saved without a tet mesher, so every SF case was confirmed on voxels, which read safe-side heavy. With tet confirm the same ab4bf9e code gives mbb-beam 15.7 g, so most of mbb-beam (22.2 -> 14.3 g), grip-wrist-yoke (24.0 -> 17.2) and grip-turret (145 -> 138) is the confirm, not the optimizer.
  - wall-bracket (81.9 -> 23.0 g) and corpus-bracket-1 (139.9 -> 36.0) are df2521f, goal.method "auto" picking the constrained optimizer (search alone still gives 72.3 g wall bracket on both ab4bf9e and today's main). Both pass the tet confirm (wall bracket SF 3.40 vs goal 2.5). **Caveat:** the 23-24 g wall bracket buckles at a load factor of 1.43-1.61 (linear buckling, 1.2 mm grid), below the 2.5 goal; the 72 g search design reads 43.5. No buckling check runs in verify or the evals yet, so this baseline locks in a part that is strong enough but not stable enough.

- **2026-11-04 (buckling in the constrained optimizer, bucklingopt.py).** wall-bracket and corpus-bracket-1 rows re-run and replaced (other cases do not reach the constrained method's buckling constraint; the full tier moved none of them): wall-bracket 46.6 -> 25.2 g massAtTarget (best 27.6 g, SF 3.22, buckling 4.97), corpus-bracket-1 39.0 -> 36.8 g (buckling 5.77).

## full.json history

- **2026-11-04 (buckling in the constrained optimizer, bucklingopt.py).** First full re-save with the buckling check on, 15/15 pass, two cases at a time; wall-bracket and wall-bracket-fasteners rows are from reruns with the final code (faster eigensolve, PARDISO fallback on hinged designs). Moves vs 33ced02 (massAtTarget):
  - wall-bracket 26.9 -> 27.4 g and wall-bracket-fasteners 26.5 -> 27.2 g, but now stable: the old ~26 g parts buckled at 1.4-1.6x for a 2.5 goal; the new ones read buckling 3.15 / 3.93 (tet SF 2.73 / 2.92). Without the optimizer constraint the check alone sent the wall bracket to 46.6 g (coarse) and 65.7 g (full, search part).
  - printed-hook 23.9 -> 29.3 g (+23%): buckling governs it now (2.61 for 2.5, SF 3.58); it runs the search, not the constrained method.
  - motor-mount +11% massAtTarget with the same best part (27.6 g, SF 3.65): the Pareto interpolation, not the design. mbb-beam +5.6% (buckling off): run-to-run tet spread.

- **2026-11-03 (main 6c97b57 plus the cast fix in this commit).** Re-saved with a tet mesher installed (pytetwild), 15/15 pass, two cases at a time, ~5 h wall on the 4-core box. Moves vs the Nov 1 baseline (massAtTarget):
  - wall-bracket 61.4 -> 26.9 g and wall-bracket-fasteners 40.3 -> 26.5 g: goal.method "auto" now picks the constrained optimizer (df2521f). Same buckling caveat as coarse.json: the ~25 g brackets are strong enough but buckle below the 2.5 goal; no buckling check runs in the evals.
  - grip-wrist-yoke -16%, printed-hook -11%, motor-mount -9%, arm-link-driven -7%, mbb-beam -5%: mostly the stem smoothing (6c3c642) and the tet confirm reaching layered parts; consistent with the coarse tier.
  - grip-wrist-link-mjf +9% (31.3 -> 34.2 g; best outcome 31.4 -> 40.2 g): the stem smoothing. With it off (ReconstructOptions(axial=False)) the same code gives 31.4 g, the old number. With it on, the 0.0525 volume-fraction outcome reads SF 0.11 on voxels (1.20 off) and its retry splits into two bodies, so the search stops at 0.056. Thin (1.8 mm) MJF members lose more of the mesh with the axial pass. Followed up 2026-11-04 (no baseline change): the one-pass axial average is biased outward on round members (distance to a convex surface is convex), so thin members shrink: the wrist link meshes 2-4% light at every density, a two-cell graded rod loses 15%. A debiased average (`ReconstructOptions(axial_debias=True)`, or `resolution.keepThinMembers`) keeps their volume and gives 33.2 g here, but on by default the full tier went mbb-beam +8.7% and motor-mount +11.9% (hook +3.7%, wrist yoke +2.8%), so it stays opt-in. Re-meshing six fixed wrist link densities with off / one-pass / debiased smoothing, the voxel-verified SF swung 2-3x between near-identical meshes (its peak sits on 1.3 mm sub-cell struts on 2.44 mm cells): the 31.4 vs 34.2 g gap is mostly search noise on this case, not a reconstruct defect.
  - bell-crank +6% (22.0 -> 23.4 g): within the ~3% run-to-run tet spread plus a search step; not chased.
  - arm-link-cast: with the stem smoothing it failed its undercut check (630 mm^3 vs 150); reconstruct now skips the axial pass on cast/milled studies, back to 141 mm^3 and 50.7 g.
  - grip-turret's tet cross-check still reads SF 1.58 at the J1 hub (voxel confirm 2.85; known, interfaces question open).
- **2026-11-04 (ccbe960).** Re-saved after the buckling check (a safety factor now has to hold against linear buckling too, `goal.buckling`, default on), 21/21 pass. wall-bracket 23.0 -> 46.6 g massAtTarget: the constrained designs buckled (1.4-1.6x vs 2.5) and now fail, so the search's part is delivered (buckling factor 11.0). corpus-bracket-1 36.0 -> 39.0 g (+8%) and printed-hook 26.7 -> 28.1 g (+5%, noise level; buckling 2.97 for 2.5). Other moves (turret -10%, yoke -18%, corpus-bracket-4 -33%) came from commits merged to main in between, not from this change. mbb-beam reports buckling 0.29 (the planar truss sways sideways) with `buckling: false` in its case.
